🔍 مفهوم گلوگاه (Bottleneck)

تعریف: وقتی یک منبع به ظرفیت می‌رسد و کل سیستم را کند می‌کند، حتی اگر بقیه منابع آزاد باشند.
🧠

CPU

پردازنده — اجرای دستورات، محاسبات

💾

Memory

حافظه — داده‌های فعال در دسترس

💽

Disk

ذخیره‌سازی — خواندن/نوشتن پایدار

🌐

Network

ارتباطات — انتقال داده بین سیستم‌ها

⚠️ قانون طلایی: همیشه همه چهار منبع را با هم بررسی کن — یک منبع تنها هرگز تصویر کامل نمی‌دهد.

📊 Task Manager

Ctrl + Shift + Esc

✅ مزیت‌ها

  • سریع‌ترین راه تشخیص اولیه
  • نمودار زنده و بلادرنگ
  • دسترسی بدون نصب

⚠️ محدودیت‌ها

  • جزئیات دقیق فایل/پروسه را نمی‌دهد
  • تاریخچه ندارد

تب‌های مهم

  • Processes: مصرف هر برنامه + ستون GPU
  • Performance: نمودار زنده + خلاصه
  • App History: مصرف تاریخی برنامه‌ها
  • Startup: برنامه‌های بوت + تأثیر
  • Users: مصرف هر کاربر
  • Details: جزئیات کامل پروسه
  • Services: سرویس‌های ویندوز

🔬 Resource Monitor

Win + R → resmon
🧠

CPU

مصرف هر پروسه + Wait Chain + Services

💾

Memory

Hard Faults — خطاهای سخت + Commit

💽

Disk

فایل در حال خواندن/نوشتن + Queue

🌐

Network

ارتباط با آدرس‌های شبکه + TCP Connections

💡 Hard Faults = خواندن از Page File — نشانه کمبود RAM. اگر مجموعش مداوم بالای ۱۰۰ باشد، RAM کم است.
🔎 Wait Chain: کدام پروسه منتظر کدام پروسه است — برای عیب‌یابی قفل‌شدگی عالی است.

📈 Performance Monitor

Win + R → perfmon
📌

Counter

شاخص اندازه‌گیری‌شده — مثلاً % Processor Time

📦

Data Collector Set

مجموعه Counterها در یک فایل لاگ (BLG/CSV)

⏱️

Sample Interval

هر ۱۵ ثانیه برای مانیتورینگ طولانی، هر ۱ ثانیه برای تحلیل دقیق

⭐ تنها ابزاری که مشکل گذشته را تحلیل می‌کند — لاگ بگیر، بعداً تحلیل کن.
# ساخت Data Collector Set از خط فرمان logman create counter "PerfLog" -c "\Processor(_Total)\% Processor Time" "\Memory\Available MBytes" -si 15 -f bincirc -max 500 logman start "PerfLog"

🧠 عیب‌یابی CPU

0%CPU Usage
\Processor(_Total)\% Processor Time

علل رایج:

  • Loop بی‌پایان در یک پروسه
  • بدافزار ماینینگ
  • درایور قدیمی یا ناسازگار
  • Process Queue Length بالای ۲×Core
CPU Usage — 24h
⚠️ آستانه: بالای ۸۰٪ به‌مدت بیش از ۵ دقیقه = گلوگاه CPU.

💾 عیب‌یابی حافظه (RAM)

0%RAM Used
\Memory\% Committed Bytes In Use

علائم کمبود:

  • کندی جابه‌جایی بین برنامه‌ها
  • صدای زیاد دیسک (Page File)
  • مصرف ناگهانی دیسک
  • Hard Faults مداوم بالای ۱۰۰
RAM Distribution
⚠️ آستانه: Available MBytes زیر ۱۰٪ کل RAM = فشار حافظه. Pages/sec بالای ۱۰۰۰ = Page File سنگین.

🧪 سه مطالعه موردی واقعی

  • مورد ۱ — کندی صبحگاهی: هر روز صبح سیستم ۱۰ دقیقه کند است. تشخیص: Task Scheduler یک اسکریپت پشتیبان‌گیری سنگین در ساعت ۸ صبح اجرا می‌کند. راه‌حل: تغییر زمان به ۳ بامداد.
  • مورد ۲ — دیسک ۱۰۰٪ بدون دلیل: هیچ فایلی در حال انتقال نیست ولی Disk Time روی ۱۰۰٪ قفل است. تشخیص: سرویس Windows Search در حال ایندکس مجدد است. راه‌حل: محدود کردن محدوده ایندکس یا غیرفعال‌سازی موقت.
  • مورد ۳ — RAM تمام‌شده با برنامه‌های کم: فقط مرورگر باز است ولی RAM پر است. تشخیص: یک extension مخرب در مرورگر در حال مصرف حافظه است. راه‌حل: حذف extension + اسکن کامل.
  • درس مشترک: همیشه از داده پشتیبانی کن — قبل از هر اقدامی، لاگ perfmon و خروجی Task Manager را ذخیره کن.
